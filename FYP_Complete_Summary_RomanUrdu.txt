================================================================================
SECTION 1: PROJECT KYA HAI?
================================================================================

Yeh ek AI-based web platform hai jo QA Engineers ke liye banaya gaya hai.

Masla kya tha:
  - QA Engineers ko manually code mein bugs dhundne padte the
  - Iska bohat waqt lagta tha aur galtiyan hoti thin
  - Koi automated system nahi tha jo bug ki wajah aur fix bhi bata sake

Humara solution:
  - User apna code file ya ZIP upload karta hai
  - AI model automatically bugs detect karta hai
  - System bata deta hai: bug kahan hai, kya hai, kyun hai, aur kaise fix karein
  - PDF report bhi generate hoti hai

Project ka full naam:
  "AI Powered Bug Detection and Resolution Platform for QA Engineers"

Kya Hai:
  Claude ek advanced language model hai (Anthropic ka). Hum ise har detected
  bug ko "enhance" karne ke liye use karte hain.

Simple Mode vs Claude Mode:

+------------------+----------------------------+-------------------------+
| Comparison       | Simple Mode (ML only)      | Claude AI Mode          |
+------------------+----------------------------+-------------------------+
| Speed            | ~3 seconds per file        | ~10-30 seconds per bug  |
| API Call         | Koi nahi (local)           | Anthropic API call      |
| Description      | Template-based             | Custom, detailed        |
| Corrected Code   | Generic template           | Actual code fix         |
| Cost             | Free                       | Claude API credit       |
| Best for         | Quick analysis             | Deep detailed review    |
+------------------+----------------------------+-------------------------+

Claude se milne wala result (per bug):
  1. claude_description   — Bug ka detailed explanation
  2. claude_reason        — Technical wajah (metrics ke reference ke saath)
  3. claude_corrected_code — Actual corrected code (real code!)
  4. claude_fix_explanation — Kyun yeh fix sahi hai

Model used: claude-haiku-4-5-20251001 (fast + affordable)

Kahan Toggle hai: Settings page → purple card → switch on/off

SECTION 11: .PKL vs .PT vs .H5 — PURA FARQ SAMJHAO
================================================================================

YEH TEEN MODEL FORMATS HAIN — TEEN ALAG DUNIYAAN:

+--+-----------+------------------+-------------------------+---------------+
|# | Format    | Library          | Model Type              | Kab Use Hota  |
+--+-----------+------------------+-------------------------+---------------+
|1 | .pkl      | Scikit-learn     | Tree-based ML models    | Har jagah     |
|  |           | XGBoost, joblib  | (XGBoost, RF, SVM etc)  | classic ML    |
+--+-----------+------------------+-------------------------+---------------+
|2 | .pt       | PyTorch          | Neural Networks         | Deep Learning |
|  | (.pth)    |                  | (CNN, RNN, LSTM etc)    | research      |
+--+-----------+------------------+-------------------------+---------------+
|3 | .h5       | TensorFlow/Keras | Neural Networks         | Production DL |
|  |           |                  | (same as .pt lekin      | ke liye       |
|  |           |                  | Keras format mein)      |               |
+--+-----------+------------------+-------------------------+---------------+

DETAIL MEIN SAMJHAIN:

----[ .PKL — Pickle File ]----------------------------------------------------

  Kya hai: Python ka built-in serialization format
           joblib library se save hota hai (sklearn models ke liye best)

  Kab use hota hai:
    - XGBoost, Random Forest, Gradient Boosting
    - SVM, Logistic Regression, KNN
    - Koi bhi scikit-learn model

  Fayde:
    + Bohat fast save/load hota hai
    + Tree-based models ke liye PERFECT
    + Koi GPU nahi chahiye
    + Chota size (features mein numbers hain, pixels nahi)
    + Easy to use: joblib.dump() aur joblib.load()

  Nuqsaan:
    - Sirf Python mein kaam karta hai
    - Deep learning ke liye suitable nahi

  Humara use:
    best_defect_model.pkl = XGBoost + RF + GradientBoosting ensemble
    bug_type_model.pkl = Random Forest classifier

----[ .PT / .PTH — PyTorch File ]---------------------------------------------

  Kya hai: PyTorch neural network weights save karne ka format
           torch.save() se save hota hai

  Kab use hota hai:
    - CNN (image recognition)
    - RNN, LSTM (sequence/text data)
    - Transformer models (BERT, GPT style)
    - Yani jab INPUT images ya text ho

  Fayde:
    + Flexible, research ke liye best
    + GPU training support
    + Complex architectures bana sakte hain
    + Transfer learning asaan

  Nuqsaan:
    - Zyada complex code likhna parta hai
    - Training ke liye GPU chahiye (warna bohat slow)
    - Hamara data (CK metrics = 20 numbers) ke liye overkill hai

----[ .H5 — HDF5 File (Keras/TensorFlow) ]------------------------------------

  Kya hai: Keras ka default save format
           TensorFlow + Keras mein use hota hai

  Kab use hota hai:
    - Keras se banaye gaye neural networks
    - Image classification, NLP tasks
    - Production deployment (TensorFlow Serving)

  Fayde:
    + Model architecture + weights dono save hote hain
    + TensorFlow ecosystem ke saath perfect
    + Production ke liye reliable

  Nuqsaan:
    - Sirf Keras/TF ke liye
    - Hamara data ke liye zarurat nahi thi


----[ HAMNE .PKL KYUN CHOOSE KIYA ]------------------------------------------

  Hamara data:
    - Input = 20-35 CK metrics (cbo, wmc, rfc, lcom, loc etc.)
    - Yeh NUMBERS hain, images ya text nahi
    - Har file se sirf ek row of numbers milti hai

  .pt ya .h5 kyun nahi:
    - Neural network ke liye images ya sequences chahiye
    - 20 numbers ke liye neural network banana = ek car se
      samose dhone ke barabar (overkill + slow)
    - Training ke liye GPU chahiye jab nahi tha humare paas
    - Accuracy bhi zyada nahi aati tree models se

  .pkl kyun perfect tha:
    - XGBoost duniya ka best tree model hai tabular data ke liye
    - Hamari accuracy: 87% AUC — yeh bahut acha hai
    - Bug type classification: 99% accuracy
    - Fast train, fast predict, koi GPU nahi chahiye

  Comparison (hamara data ke liye):

  +-------------------+-----------+------------+----------+
  | Approach          | Accuracy  | Speed      | GPU Need |
  +-------------------+-----------+------------+----------+
  | XGBoost (.pkl)    | 87% AUC   | Seconds    | Nahi     |
  | Neural Net (.pt)  | ~80-85%   | Minutes    | Haan     |
  | Keras (.h5)       | ~80-85%   | Minutes    | Haan     |
  +-------------------+-----------+------------+----------+

  Tabular data (numbers) pe XGBoost HAMESHA neural network se
  better ya equal perform karta hai — yeh proven research hai.


----[ KYA HUM .PT MEIN BADAL SAKTE HAIN? ]-----------------------------------

  Technically: Haan, badal sakte hain

  Kaise:
    - PyTorch mein ek small neural network banao
    - Input layer: 35 neurons (features)
    - Hidden layers: 128 → 64 → 32
    - Output: 1 neuron (defect probability)
    - save: torch.save(model.state_dict(), "model.pt")

  Lekin kyun nahi karenge:
    1. Accuracy GIRAY GI (tabular data mein .pkl better hai)
    2. Training slow hogi (GPU ke bina ghanton lagenge)
    3. Humari current accuracy (87% AUC) excellent hai
    4. Client ko results chhiye, format nahi
    5. System abhi perfect kaam kar raha hai

  Bottom line:
    .pkl = sahi tool, sahi kaam ke liye
    .pt = alag kaam ke liye (images, text, deep learning)
